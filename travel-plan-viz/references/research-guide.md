# 联网调研指南

生成页面前，用你所在 Agent 的**联网搜索 / 网页抓取工具**补全数据（如 Claude Code 的 WebSearch/WebFetch、Codex 的联网能力等）。机票给**建议班次**，价格按下方「航班」节的渠道规则查（2026-08-21 起旧「不查实时票价」红线已废除）。

## 第三方 skill 适配（可选增强，有则用、无则降级）

调研开始前，先判断**当前 Agent 是否可调用相关官方旅行类 skill / MCP**（用户自行安装的，如飞猪、高德、腾讯地图、滴滴等）。**有就优先用它们拿对应数据，没有就走本指南后面的静态调研**——两条路产出同一套 `trip` 数据结构，成品不因缺这些 skill 而残缺。

下表为各家公开能力盘点（2026-06 调研一手开放平台文档，**以各家官方文档实时为准**，能力会变）：

| 用户若装了 | 可优先用它拿（对应咱们哪个功能） | 备注 |
|------|------|------|
| **高德地图** MCP/skill（增强面最大，多数工具开箱即用） | **地理编码 → 精确坐标**（替代"搜经纬度"猜）；**公交/驾车/步行/骑行路径规划 → 点到点交通**（实时路况+多方案）；**天气查询 → 行前须知天气**；**POI 关键词/周边/详情搜索 → 景点&酒店信息**；**生成专属地图 → 整条行程唤端地图链接**；**导航/打车 → actionLink** | 调研到 15 个工具，是命中咱们薄弱点最多的一家。官方入口具名（2026-07 核）：**高德官方 MCP Server**（lbs.amap.com「大模型开发工具」入口）与 OpenClaw 平台 skill **`amap-lbs-skill`**（GitHub org `AMap-Web`），均需用户自备 Web 服务 Key |

## 本地可选工具：xhs_research（小红书攻略素材，软依赖）

若本机配置了 `tools/xhs_research.py`（Python + Playwright，安装与登录见 `tools/README.md`），调研目的地的**玩法/路线/避坑/节奏**时可让它按「<目的地> 攻略」抓一批社区笔记作参考素材；没配置就跳过，不影响任何区块。三条边界：

1. **素材仅作定性参考**：笔记里的坐标、票价、营业时间、班次**一律不直接采信**，仍按本指南各节规则另行核实——社区内容时效性与准确性无保证，坐标系也可能混着 GCJ-02。
2. **图片不走小红书 CDN**：成品页面图片仍只走 Wikimedia FilePath + 200 校验，别拿笔记里的图。
3. **礼貌抓取**：保持脚本默认条数与延时，别为"多抓点"调大参数；仅个人调研用途。
4. **工具不可用时的降级**：没装 Playwright 或未登录时，用联网搜索查「小红书 <目的地> 攻略」——搜索引擎能带出部分笔记内容，作降级参考（内容同样只作定性参考，边界同上）。

## 本地可选工具：flight_research（机票实时价，飞猪 FlyAI 直连）

`tools/flight_research.py` 用**用户自备**的飞猪 FlyAI API Key 查某条航线某天的航班候选与实时价，输出 JSON + Markdown（含查询时间戳），填进 `flights.candidates`。仅标准库、零第三方依赖；没配 Key 就跳过，不影响任何区块。边界：

1. **Key 用户自备**：`FLYAI_API_KEY` 环境变量或 `--key-file`（flyai.open.fliggy.com 控制台申领）。**Key 绝不写进仓库、成品页或对话记录。**
2. **端点以官方文档为准**：文档在登录墙后，脚本顶部的 base/path/鉴权头常量是占位——首跑 401/404 先对照官方文档核对，或用 `--base`/`--path` 覆盖；解析器按多返回形态容错（改完 `selftest` 必须绿）。
3. **结果带时间戳与来源**：写入页面时登记 `dataSources`、candidates 附 `priceQueriedAt`，措辞「价格随订位实时变动，以订票页为准」；不代订、不背书。
4. **优先级**：用户已装飞猪 skill 就先用 skill（免 Key 即装即用）；本工具是无 skill 机制的 Agent 或脱会话批查时的兜底。

**坐标系陷阱（用高德/腾讯必读）**：高德与腾讯地图返回的坐标是 **GCJ-02**（国测局加密坐标），而本 skill 的地图用 OSM 瓦片（**WGS-84**）。直接把 GCJ-02 坐标写入 `trip`，中国境内点位会系统性偏移一百到几百米——恰好制造你想避免的"坐标错位翻车"。**凡来自高德/腾讯的坐标，写入前必须用 `assets/map.js` 的 `gcj02ToWgs84(lat, lng)` 转换**（境外坐标该函数会原样返回，多转不会错）。静态调研（维基/搜索）拿到的坐标一般已是 WGS-84，不用转。

**具体示例（点到点交通）**：本指南的「点到点交通」默认是静态调研出一个方式+票价+耗时。若用户装了高德/腾讯地图 skill，改用它的**路线规划**（高德有公交/驾车/步行/骑行四种，公交含火车/地铁/公交综合方案），拿到结合**实时路况**的多方案（更科学合理），并把官方返回的导航链接作为该节点的 `actionLink`。另一个高价值点：用高德**地理编码**拿精确坐标，比"搜名称+经纬度"可靠得多（坐标错位是地图最常见的翻车点）。

**三条铁律（破了就违背架构红线）**：
1. **责任边界**：用官方 skill 拿来的数据，其**实时性与真实性由该官方 skill 负责**，我们只做适配编排，不自行复核也不背书。
2. **标注来源 + 中性措辞**：凡用官方 skill 拿的数据，在页面对应区块注明数据来源（如「实时数据来源：高德地图 skill，时效性由其保证」），与 AI 静态整理的内容（标"参考·可能过时"）区分开；**用中性工程措辞，不夸、不推荐、不替任何一家打广告**。
3. **行动链接只用官方返回的**：`actionLink` 的 URL **优先用官方 skill 返回的链接**（带正确参数最稳）；**不要手拼 deeplink / URL scheme**（易失效）。官方 skill 不在场时，宁可不加行动链接，也别放可能打不开的手拼链接。（此禁令针对 actionLink；`map.js` 引擎按官方免 key URI 规范生成的「高德地图 / Google 地图」点位链接不在此列，边界见 page-contract「可选适配元素」。）

> 机票实时价只经官方渠道——用户已装的官方 skill，或 `tools/flight_research.py` 官方 API 直连（key 用户自备）；查到的数据须标来源与查询时间戳，页面注明以订票页为准。仍不爬 OTA、不代订、不背书。详见 page-contract 的 `dataSources` 与节点级 `actionLink` 字段。

## 每个景点/酒店需采集

- **文保等级（如有，优先采集）**：第 X 批全国重点文物保护单位 / 世界文化遗产 / 5A 等——权威背书，是景点清单排序的**重要权重**（高含金量文保显著上浮，但不唯文保论）；批次号以国家文物局/世遗官网名录为准联网核实，**别凭记忆写**。
- 坐标（lat/lng）：搜索"<名称> 经纬度 / coordinates"，或从地图类结果取。
- 真实图片 URL（**务必能加载**）：
  - **不要手拼** `upload.wikimedia.org/.../thumb/X/XX/...` 这种带哈希前缀的直链——哈希猜错就 400/404。
  - 用稳健形式：`https://commons.wikimedia.org/wiki/Special:FilePath/<URL编码的文件名>?width=600`，它会自动重定向到正确缩略图，无需哈希。文件名取自该图在 Commons 的真实文件名。
  - **每个图片 URL 都要 `curl -s -o /dev/null -w "%{http_code}" -L <url>` 验证返回 200 才用**；非 200（文件不存在等）就换一张真实存在的图，实在没有就留空走 onerror 降级，绝不放已知打不开的链接。

### 图片按优先级后补（不阻塞正文，2026-08-21 拍板）

**攻略正文优先**：坐标/时刻/票价/天气/酒店/餐饮等正文数据齐了就先生成交付，图片后补——**允许先出无图版**（`photo` 留空走统一降级），别为长尾图拖着正文不交付。补图规则：

1. **优先级排序**：门面/顶流景点 → 行程核心/国保孤本 → 古镇古堡 → 自然/长尾。每点 1–2 张即可，宁缺毋滥；P0+P1 补完即可出带图版，长尾有则带上、无则留空。
2. **Commons 礼貌抓取（实测教训）**：存在性摸底用**一次批量 imageinfo API**（一个请求查全部文件名，不触发限流）；逐 URL 的 200 校验**留 ≥8 秒间隔**并带 `curl --retry 4 --retry-delay 20 --retry-all-errors` 退避——1 秒一个连发的话，`Special:FilePath` 重定向第 5 个起就吃 429（实测连续 21 个 429）。已确认过 200 的 URL 别重复验证。页面 `<img>` 建议加 `referrerpolicy="no-referrer"`。
3. **归属核验防张冠李戴**：认文件页的 Category/坐标，确认是本尊（如「府城玉皇庙」而非同市其他玉皇庙）；**同景区通用图**（如用青龙潭图配八泉峡）可用，但须在 slot `note` 里如实标注「配图为同景区 XX」。
4. **后补方式**：过审 URL 填进 trip-data 对应 slot 的 `photo` 字段重渲染即可（数据与呈现分离的红利），不动其他字段。
- 评分：来自点评类来源的概览分（注明是概览，非实时）。
- 一句话点评：综合调研后用一句中文概括亮点。
- 营业时间 + 休息日（如"12:30–22:30，周日休"）：搜索"<名称> 营业时间 opening hours"。
- **开放状态冲突仲裁**：官方闭园公告可能滞后于实际恢复（社区实拍/用户反馈往往更新更快，且排险类闭园常是周期性的、恢复不另行公告）。冲突时**不硬选边**——景点可上清单，但节点标注「行前务必核实开放状态」，并把"确认 XX 已恢复开放"写进 `reminders` 待办（leadDays 3 左右）。
- 门票参考价（如有）：给区间或单价，注明为参考、非实时。

## 行前须知（按出发日期/季节定制）

- 天气：搜索"<城市> <出发月份> 天气 平均气温 降雨"，给气温区间、降雨规律（如午后雷暴）、台风/极端天气季节提醒。
- 穿搭：据天气给具体建议（含室内空调偏冷等本地常识）。
- 支付：当地主流支付方式（如香港八达通）、是否需备现金。
- 必备 App：交通、天气、热门景点排队等。
- 购票时机：热门景点建议提前几天网上购票。

## 点到点交通

- 为关键行程点给出"如何到达"：方式（自驾/地铁/巴士/缆车/轮渡/步行）、参考票价、耗时，写入 slot 的 `transport`。搜索"<A> 到 <B> 怎么走 交通"。机场往返单独给（如机场快线 vs 巴士的价/时对比）。
- **任何交通方式都必须给「逐段点到点交通链」**（2026-08-21 拍板泛化，不限自驾/包车）：住宿点→首站、景点→景点、末站→住宿点，每段**方式 + 耗时**缺一不可——自驾/包车再加距离、公共交通再加票价与班次密度——散在贴士里的零星车程不等于成链。**每日链条的起点必须是前一晚的住宿点**（写错起点会把车程低估一半，实测 D4 把「晋城→王莽岭」写成了实际应从北留出发）。自驾估算方法：用调研到的 WGS-84 坐标算直线距离 × 道路系数（平原/高速约 1.3、山区约 1.6–2.0），用已核实的锚点腿标定；**赶开场/首班索道/航班的关键腿联网核实或以导航复核**，并反推出发时刻（如"赶 8:00 开城须 7:00 出发"）。页面标注为估算、以导航实测为准。
- **天黑不走山路（安全硬约束，2026-08-21 拍板）**：日落后只允许走高速/国道/少量平原省道，**任何山路段不得排在日落前后走**。排程时查目的地当季日落时刻，逐日核验当日最后一段山路——保守留 30 分钟以上余量，赶不上就调整：末站提前收、住宿点前移、或该段绕行高速（实测整改：锡崖沟→陵川 50km 山路若 17:00 后出发即摸黑，改宿王莽岭山上根除）。清晨同理：摸黑出发的山路须等日出。

## 航班（待选，给建议班次）

- **查询时机**：整体攻略（景点清单+天数）对齐之后、逐日方案之前（见 SKILL.md 模式 A 第 4 步）——首尾两天的排程要以真实班次时刻为约束，别排好行程再硬凑；出发日期未定（dateTBD）则推迟到定档后/调研补全阶段，别空查。
- **出发城市来自「需求澄清」步骤**（见 SKILL.md 模式 A 第 1 步）；用户没给就先问，不要按直觉猜一个。
- 用户未预订时，**给 3-5 个建议班次**（不要只给一个，万一订不上有备选）：航司 + 航班号 + 起降时刻。**航班号要联网核实当季真实存在**——航线换季会停开，别凭记忆写。
- **价格按渠道优先级**：① 用户已装的飞猪 flyai skill（免 Key 即装即用，首选）；② `tools/flight_research.py` 官方 API 直连（key 用户自备，用法见 `tools/README.md`）；③ 都没有 → 联网搜"<出发地>到<目的地> 机票 价格"给**参考区间**并注明非实时。走 ①② 拿到实时价的：candidates 写 `price` + `priceQueriedAt`、`dataSources` 登记来源，页面注明「价格随订位实时变动，以订票页为准」。
- `note` 写机型/是否直飞/经停等乘机信息。
- 已预订的（用户告知）单独高亮，标"已预订"。
- **目的地无民航机场时**（如晋城）：给「最近机场 + 高铁/大巴接驳」组合方案（机场进城交通耗时一并给），高铁段也列建议车次（同条规则：真实存在、给参考票价、标注以 12306 为准）。

## 酒店（按片区 + 价位推荐，不指定单一酒店）

- 先看本次行程各景点的地理分布，**综合选 1-2 个建议住宿片区**（如香港多落在尖沙咀/中环/铜锣湾），写明推荐理由（离哪些点近、交通如何）。
- 每个片区按 `经济 / 中档 / 高端` 三档各给 1 个真实存在的代表酒店：名称 + 大致每晚价位区间 + 一句话说明（位置/特点）。价位为区间参考，非实时房价。
