# 联网调研指南

生成页面前，用你所在 Agent 的**联网搜索 / 网页抓取工具**补全数据（如 Claude Code 的 WebSearch/WebFetch、Codex 的联网能力等）。机票给**建议班次**，价格按下方「航班」节的渠道规则查（2026-08-21 起旧「不查实时票价」红线已废除）。

## 第三方 skill 适配（可选增强，有则用、无则降级）

调研开始前，先判断**当前 Agent 是否可调用相关官方旅行类 skill / MCP**（用户自行安装的，如飞猪、高德、腾讯地图、滴滴等）。**有就优先用它们拿对应数据，没有就走本指南后面的静态调研**——两条路产出同一套 `trip` 数据结构，成品不因缺这些 skill 而残缺。

下表为各家公开能力盘点（2026-06 调研一手开放平台文档，**以各家官方文档实时为准**，能力会变）：

| 用户若装了 | 可优先用它拿（对应咱们哪个功能） | 备注 |
|------|------|------|
| **高德地图** MCP/skill（增强面最大，多数工具开箱即用） | **地理编码 → 精确坐标**（替代"搜经纬度"猜）；**公交/驾车/步行/骑行路径规划 → 点到点交通**（实时路况+多方案）；**天气查询 → 行前须知天气**；**POI 关键词/周边/详情搜索 → 景点&酒店信息**；**生成专属地图 → 整条行程唤端地图链接**；**导航/打车 → actionLink** | 调研到 15 个工具，是命中咱们薄弱点最多的一家。官方入口具名（2026-07 核）：**高德官方 MCP Server**（lbs.amap.com「大模型开发工具」入口）与 OpenClaw 平台 skill **`amap-lbs-skill`**（GitHub org `AMap-Web`），均需用户自备 Web 服务 Key |
| **飞猪 flyai** skill/MCP（实时直连官方库，结果可真实预订） | **机票搜索 → 航班候选+实时价**；**酒店 → 酒店片区**；**火车票 → 交通备选**；**景区门票/度假 → 门票**；均返回**真实预订链接**作 actionLink | skill 路线**免 Key**（官方 SKILL.md 装入 `~/.claude/skills/flyai` + `npm i -g @fly-ai/flyai-cli`，装法以 flyai.open.fliggy.com 为准）；直连 API 需 Key（同站申领，淘宝账号+支付宝实名，5000 次免费，见 `tools/flight_research.py`）。**CLI 体验模式实测（2026-08-24，免 Key）**：机票给精确价+航班号/时刻/航站楼+飞猪预订链（国内+国际），酒店给候选/星级/坐标/详情链但**价格打码（¥1xx）、评分为空**——精确房价需正式 Key。CLI bundle 用了较新 JS 语法，**需 Node ≥14**（老 Node 可用 bun 等现代运行时跑 bundle）。**飞猪返回的酒店/POI 坐标是 GCJ-02**，入 trip 前须经 `map.js` 的 `gcj02ToWgs84` 转换 |
| **腾讯位置服务** skill/MCP（能力与高德重叠，开发向更重） | 路线规划、POI 搜索（8000 万+）、地址服务、实时路况导航；另有 3D/室内地图（一般用不上） | 多与高德二选一即可 |
| **滴滴** MCP/skill | **打车全流程**（叫车/预估/跟踪/取消）→ 交通的用车方案与**叫车唤端链接**；也有驾车/公交/步行/骑行路线规划 | Beta 版返回跳转链接 |

没装任何一家时，全部走本指南后面的静态调研，成品不缺区块。

## 本地可选工具：xhs_research（小红书攻略素材，软依赖）

若本机配置了 `tools/xhs_research.py`（Python + Selenium + Chrome，安装与登录见 `tools/README.md`），调研目的地的**玩法/路线/避坑/节奏**时可让它按「<目的地> 攻略」抓一批社区笔记作参考素材；没配置就跳过，不影响任何区块。三条边界：

1. **素材仅作定性参考**：笔记里的坐标、票价、营业时间、班次**一律不直接采信**，仍按本指南各节规则另行核实——社区内容时效性与准确性无保证，坐标系也可能混着 GCJ-02。
2. **图片不走小红书 CDN**：成品页面图片仍只走 Wikimedia FilePath + 200 校验，别拿笔记里的图。
3. **礼貌抓取**：保持脚本默认条数与延时，别为"多抓点"调大参数；仅个人调研用途。
4. **工具不可用时的降级**：没装 Selenium 或未登录时，联网搜「小红书 <目的地> 攻略」**基本搜不到站内笔记**（2026-08-23 实测：小红书内容不进通用搜索引擎）——降级走「网友实测情报挖掘」节的信源降级链（旅记长文/订房平台差评摘译），内容同样只作定性参考，边界同上。

## 本地可选工具：flight_research（机票实时价，飞猪 FlyAI 直连）

`tools/flight_research.py` 用**用户自备**的飞猪 FlyAI API Key 查某条航线某天的航班候选与实时价，输出 JSON + Markdown（含查询时间戳），填进 `flights.candidates`。仅标准库、零第三方依赖；没配 Key 就跳过，不影响任何区块。边界：

1. **Key 用户自备**：`FLYAI_API_KEY` 环境变量或 `--key-file`（flyai.open.fliggy.com 控制台申领）。**Key 绝不写进仓库、成品页或对话记录。**
2. **端点以官方文档为准**：文档在登录墙后，脚本顶部的 base/path/鉴权头常量是占位——首跑 401/404 先对照官方文档核对，或用 `--base`/`--path` 覆盖；解析器按多返回形态容错（改完 `selftest` 必须绿）。
3. **结果带时间戳与来源**：写入页面时登记 `dataSources`、candidates 附 `priceQueriedAt`，措辞「价格随订位实时变动，以订票页为准」；不代订、不背书。
4. **优先级**：用户已装飞猪 skill / flyai CLI 就先用它（免 Key 体验模式即用，机票给精确价）；本工具是直连 API 形态的兜底（脱会话批查、无 CLI 环境）。

## 本地可选工具：gflights_research（机票比价，Google Flights，零 Key）

`tools/gflights_research.py` 经 fli（PyPI 包名 `flights`）的 Google Flights 逆向接口查航线某天的航班候选与比价，**零 Key、即装即用**，输出 JSON + Markdown（含查询时间戳），填 `flights.candidates`。与 flight_research 是并列渠道：本工具适合没有 FlyAI Key / 没装飞猪 skill 的场合。边界：

1. **逆向接口可能失效**：Google 改版/风控随时会让它报错——失败就如实留空换渠道，别硬凑。
2. **需连通 www.google.com**：境内服务器不一定可达，先 curl 探测再跑。
3. 价格是 Google Flights 聚合报价、与出票渠道可能有差；比价深链由 fli 确定性生成（非实时订票链接）；保持低频（1 条航线 1 次查询足够）；不代订、不背书。

## 本地可选工具：hotel_research（酒店实时价，飞猪 FlyAI 直连）

`travel-plan-viz/tools/hotel_research.py` 用**用户自备**的飞猪 FlyAI API Key（与 flight_research 同一把）查某城市某入住区间的酒店候选与实时价，输出 JSON + Markdown（含查询时间戳），填进 `hotelAreas[].options` 的 `price` / `priceQueriedAt` / `actionLink`。仅标准库、零第三方依赖。**调用时机是本工具的灵魂（2026-08-21 拍板）：仅在出发日期确定后调用**——行程仍是 dateTBD（估算日）时一律不查（估算日查价无意义），页面只给参考区间 `priceRange`；用户定档并把 HTML 丢回来重算时，才逐片区查实时价回填。其余边界：

1. Key 用户自备、绝不入库/入页面/入对话记录（同 flight_research）。
2. 端点以官方文档为准（登录墙后），常量占位、`--base`/`--path` 可覆盖；改解析器（纯函数）后 `selftest` 必须绿。
3. 结果带时间戳与来源；写入页面时登记 `dataSources`，措辞「价格随订位实时变动，以订房页为准」；不代订、不背书。
4. 优先级：用户已装飞猪 skill（含酒店搜索）就先用 skill；本工具是无 skill 机制的 Agent 的兜底。每片区每晚 1 次查询即可，保持低频。

**坐标系陷阱（用高德/腾讯必读）**：高德与腾讯地图返回的坐标是 **GCJ-02**（国测局加密坐标），而本 skill 的地图用 OSM 瓦片（**WGS-84**）。直接把 GCJ-02 坐标写入 `trip`，中国境内点位会系统性偏移一百到几百米——恰好制造你想避免的"坐标错位翻车"。**凡来自高德/腾讯的坐标，写入前必须用 `assets/map.js` 的 `gcj02ToWgs84(lat, lng)` 转换**（境外坐标该函数会原样返回，多转不会错）。静态调研（维基/搜索）拿到的坐标一般已是 WGS-84，不用转。

**具体示例（点到点交通）**：本指南的「点到点交通」默认是静态调研出一个方式+票价+耗时。若用户装了高德/腾讯地图 skill，改用它的**路线规划**（高德有公交/驾车/步行/骑行四种，公交含火车/地铁/公交综合方案），拿到结合**实时路况**的多方案（更科学合理），并把官方返回的导航链接作为该节点的 `actionLink`。另一个高价值点：用高德**地理编码**拿精确坐标，比"搜名称+经纬度"可靠得多（坐标错位是地图最常见的翻车点）。

**三条铁律（破了就违背架构红线）**：
1. **责任边界**：用官方 skill 拿来的数据，其**实时性与真实性由该官方 skill 负责**，我们只做适配编排，不自行复核也不背书。
2. **标注来源 + 中性措辞**：凡用官方 skill 拿的数据，在页面对应区块注明数据来源（如「实时数据来源：高德地图 skill，时效性由其保证」），与 AI 静态整理的内容（标"参考·可能过时"）区分开；**用中性工程措辞，不夸、不推荐、不替任何一家打广告**。
3. **行动链接只用官方返回的**：`actionLink` 的 URL **优先用官方 skill 返回的链接**（带正确参数最稳）；**不要手拼 deeplink / URL scheme**（易失效）。官方 skill 不在场时，宁可不加行动链接，也别放可能打不开的手拼链接。（此禁令针对 actionLink；`map.js` 引擎按官方免 key URI 规范生成的「高德地图 / Google 地图」点位链接不在此列，边界见 page-contract「可选适配元素」。）

> 机票价格**渠道不限**（2026-08-24 拍板，废除「只经官方渠道」与「不爬 OTA」红线）：用户已装的官方 skill、`tools/flight_research.py` 官方 API 直连（key 用户自备）、`tools/gflights_research.py` Google Flights 比价（零 Key）、飞常准 MCP、本地比价工具（Google Flights 类，如 AdvSearchFlights）、OTA/聚合页面皆可。无论渠道，产出须标来源与查询时间戳，**页面声明「机票价格仅作参考、以订票页为准」（强制）**；不代订、不背书。详见 page-contract 的 `dataSources` 与节点级 `actionLink` 字段。

## 每个景点/酒店需采集

- **文保等级（如有，优先采集）**：第 X 批全国重点文物保护单位 / 世界文化遗产 / 5A 等——权威背书，是景点清单排序的**重要权重**（高含金量文保显著上浮，但不唯文保论）；批次号以国家文物局/世遗官网名录为准联网核实，**别凭记忆写**。采集入口是**名录枚举而非热度检索**：**任何行程**都必须把穿越各县的国保名录逐县拉全（境外/无国保概念的目的地对照世遗名录），第六批后的乡野国保在"必去/攻略"类热度内容里不可见。**国保/世遗必须逐条纳入考虑：可低优先级、不可无表态（2026-08-21 拍板）**——对照路线走廊逐条给入选/排除结论，值得备选的进当日 alternatives。把选中的点写准（批次核实/开放仲裁）与把该有的点摸齐是两回事，后者缺失时前者做得再好也只是精确地漏。整体优化复盘时必报「舍弃点位 Top10」（含金量排序+当初舍弃原因+翻案代价）——排除理由会随线路改版失效，不主动重捞就永远漏着（2026-08-21 拍板⑧）。
- 坐标（lat/lng）：搜索"<名称> 经纬度 / coordinates"，或从地图类结果取。
- 真实图片 URL（**务必能加载**）：
  - **不要手拼** `upload.wikimedia.org/.../thumb/X/XX/...` 这种带哈希前缀的直链——哈希猜错就 400/404。
  - 用稳健形式：`https://commons.wikimedia.org/wiki/Special:FilePath/<URL编码的文件名>?width=600`，它会自动重定向到正确缩略图，无需哈希。文件名取自该图在 Commons 的真实文件名。
  - **每个图片 URL 都要 `curl -s -o /dev/null -w "%{http_code}" -L <url>` 验证返回 200 才用**；非 200（文件不存在等）就换一张真实存在的图，实在没有就留空走 onerror 降级，绝不放已知打不开的链接。

### 图片按优先级后补（不阻塞正文，2026-08-21 拍板）

**攻略正文优先**：坐标/时刻/票价/天气/酒店/餐饮等正文数据齐了就先生成交付，图片后补——**允许先出无图版**（`photo` 留空走统一降级），别为长尾图拖着正文不交付。补图规则：

1. **优先级排序**：门面/顶流景点 → 行程核心/国保孤本 → 古镇古堡 → 自然/长尾。每点 1–2 张即可，宁缺毋滥；P0+P1 补完即可出带图版，长尾有则带上、无则留空。
2. **Commons 礼貌抓取（实测教训）**：存在性摸底用**一次批量 imageinfo API**（一个请求查全部文件名，不触发限流）；逐 URL 的 200 校验**留 ≥8 秒间隔**并带 `curl --retry 4 --retry-delay 20 --retry-all-errors` 退避——1 秒一个连发的话，`Special:FilePath` 重定向第 5 个起就吃 429（实测连续 21 个 429）。已确认过 200 的 URL 别重复验证。页面 `<img>` 建议加 `referrerpolicy="no-referrer"`。
3. **归属核验防张冠李戴**：认文件页的 Category/坐标，确认是本尊（如「府城玉皇庙」而非同市其他玉皇庙）；**同景区通用图**（如用青龙潭图配八泉峡）可用，但须在 slot `note` 里如实标注「配图为同景区 XX」。
4. **后补方式**：过审 URL 填进 trip-data 对应 slot 的 `photo` 字段重渲染即可（数据与呈现分离的红利），不动其他字段。
- 评分：来自点评类来源的概览分（注明是概览，非实时）。
- 一句话点评：综合调研后用一句中文概括亮点。
- 营业时间 + 休息日（如"12:30–22:30，周日休"）：搜索"<名称> 营业时间 opening hours"。**开放限制较大时必须写进 slot 的 `openingHours`/`closedDays`，即使当日排程已避开（2026-08-23 拍板）**——闭馆日/仅周日短开/免费时段限制（如"周日仅 14:00–18:00 开放（上午礼拜）"、"免费档仅周一至周六 8:30–9:30"）都要把限制本身写明，排程避开只是"这次没撞上"，读者改期/换线时才知道边界在哪。别把限制只写在当日 tips 里一笔带过——景点详情是随点位走的。
- **开放状态冲突仲裁**：官方闭园公告可能滞后于实际恢复（社区实拍/用户反馈往往更新更快，且排险类闭园常是周期性的、恢复不另行公告）。冲突时**不硬选边**——景点可上清单，但节点标注「行前务必核实开放状态」，并把"确认 XX 已恢复开放"写进 `reminders` 待办（leadDays 3 左右）。
- 门票参考价（如有）：给区间或单价，注明为参考、非实时。
- **联票/城市卡/年卡必查（2026-08-23 拍板）**：排完行程后主动搜「<目的地> 联票 / city pass / 通票 / 年卡」类产品——景区联票（如塞维利亚救世主教堂+大教堂联票）、城市旅游卡（如 Granada Card 48h/72h）、区域年卡（如山西文旅年卡 258 元、湖北旅游惠民卡）——逐个做**回本数学**：单买行程内景点总价 vs 卡价、卡内多出的点用不用得上、有没有时段/预约坑（如格拉纳达 48 小时卡实体卡只能在市区指定机器取、只坐红色公交），结论写进对应日 tips 或行前须知。**不划算也要如实写"算过、不值"**（如"只去阿宫+大教堂约 €30，48h 卡约 €55 不回本"）——比价结论本身就是攻略价值；核实口径：官方票务页优先，网友实测价标注年份。

## 行前须知（按出发日期/季节定制）

- 天气：搜索"<城市> <出发月份> 天气 平均气温 降雨"，给气温区间、降雨规律（如午后雷暴）、台风/极端天气季节提醒。
- 穿搭：据天气给具体建议（含室内空调偏冷等本地常识）。
- 支付：当地主流支付方式（如香港八达通）、是否需备现金。
- 必备 App：交通、天气、热门景点排队等。
- 购票时机：热门景点建议提前几天网上购票。
- **境外行程加「市内交通与交通卡」（2026-08-23 拍板）**：每城查交通卡/次票形态与参考价，写入 `preTrip.transitCards`（{city, card, price, note}）——多日卡（如 Barcelona Hola Barcelona 2–5 日）、次票（T-casual €13/10 次）、充值卡/上车刷 contactless（塞维利亚/格拉纳达单程约 €1.4–1.6）、机场线怎么算（马德里地铁机场补价 €3、巴塞 T-casual 不含机场线补价）都要点明；票价为参考、以官方为准。只有 2–3 程的短停城市就直说买单程/刷 contactless 更划算——和联票一样，**算过不值也要写**。

## 点到点交通

- 为关键行程点给出"如何到达"：方式（自驾/地铁/巴士/缆车/轮渡/步行）、参考票价、耗时，写入 slot 的 `transport`。搜索"<A> 到 <B> 怎么走 交通"。机场往返单独给（如机场快线 vs 巴士的价/时对比）。
- **任何交通方式都必须给「逐段点到点交通链」**（2026-08-21 拍板泛化，不限自驾/包车）：住宿点→首站、景点→景点、末站→住宿点，每段**方式 + 耗时**缺一不可——自驾/包车再加距离、公共交通再加票价与班次密度——散在贴士里的零星车程不等于成链。**每日链条的起点必须是前一晚的住宿点、终点必须是当晚住宿点**（写错起点会把车程低估一半，实测 D4 把「晋城→王莽岭」写成了实际应从北留出发；末段住宿腿散在链外同样丢车程，实测 D1 链曾止于崇庆寺、把 70km 住宿腿漏在链外）。自驾估算方法：用调研到的 WGS-84 坐标算直线距离 × 道路系数（平原/高速约 1.3、山区约 1.6–2.0），用已核实的锚点腿标定；**赶开场/首班索道/航班的关键腿联网核实或以导航复核**，并反推出发时刻（如"赶 8:00 开城须 7:00 出发"）。页面标注为估算、以导航实测为准。**链条里每个浏览型点位附大概浏览时长（2026-08-23 拍板）**：写成「景点名（浏览约2小时）」跟在点位名后、再接下一段车程——只有车程没有浏览时长的链条让人误判当天装不装得下；时长与当日 slot 的 `time` 字段一致（slot 已有时段就把差值带过来），交通型节点（机场/车站）标候车/值机约 X 分钟或省略，住宿节点标寄存/退房约 X 分钟。
- **天黑不走山路（安全硬约束，2026-08-21 拍板）**：日落后只允许走高速/国道/少量平原省道，**任何山路段不得排在日落前后走**。排程时查目的地当季日落时刻，逐日核验当日最后一段山路——保守留 30 分钟以上余量，赶不上就调整：末站提前收、住宿点前移、或该段绕行高速（实测整改：锡崖沟→陵川 50km 山路若 17:00 后出发即摸黑，改宿王莽岭山上根除）。清晨同理：摸黑出发的山路须等日出。
- **「导出到高德」走官方免 key URI，别发明路书接口（2026-08-22 调研定论）**：高德路书只有网页端登录后手动创建与分享页（amap.com/roadbook/<id>），**无公开创建/导入 API**——别在页面里假装能"写入路书"。官方免 key 通道里最接近的能力是 **URI API 多点标注**（`uri.amap.com/marker?markers=…`，单链接上限 **10 点**、每点可带名称，超出按序分块），页面「📍 高德打开当日点位」链接即由 `map.js` 的 `buildAmapDayMarkersLinks` 生成；注意该 URI 与导航 URI（`uri.amap.com/navigation`，via 途经点**上限 1 个**、仅驾车）的参数表都**没有 coordinate 参数**（默认 GCJ-02），坐标必须先经 `wgs84ToGcj02` 转换（引擎已内置，页面侧别自己拼）。措辞如实：链接带走的是"带名称的点集合、无连线"，收藏/存路书须用户在高德内手动操作。
- **境外尽量避免出租车（2026-08-23 拍板）**：欧洲/日本等地打车贵（欧洲市区 15 分钟常 €8–15）、还常有绕路/刷卡纠纷，主线交通一律**地铁/公交/步行/铁路优先**——车程链与 slot `transport` 里打车只能作「行李多/深夜/赶车」的兜底项出现并带参考价（写成「公交约 20 分钟（行李可打车兜底约 €8）」而非「打车 15 分钟」）；城市间接驳优先铁路+市内交通卡。网友实测的落地微操（机场大巴几号口上车、车站到市区步行几分钟、公交上车刷 contactless）一并写进链或行前须知。

## 航班（待选，给建议班次）

- **查询时机**：整体攻略（景点清单+天数）对齐之后、逐日方案之前（见 SKILL.md 模式 A 第 4 步）——首尾两天的排程要以真实班次时刻为约束，别排好行程再硬凑；出发日期未定（dateTBD）则推迟到定档后/调研补全阶段，别空查。
- **出发城市来自「需求澄清」步骤**（见 SKILL.md 模式 A 第 1 步）；用户没给就先问，不要按直觉猜一个。
- 用户未预订时，**给 3-5 个建议班次**（不要只给一个，万一订不上有备选）：航司 + 航班号 + 起降时刻。**航班号要联网核实当季真实存在**——航线换季会停开，别凭记忆写。
- **价格渠道不限（2026-08-24 拍板，废除「只经官方渠道」「不爬 OTA」红线）**：飞猪 flyai skill（免 Key 即装即用）、`tools/flight_research.py` 官方 API 直连（key 用户自备，用法见 `tools/README.md`）、`tools/gflights_research.py` Google Flights 比价（零 Key，即装即用）、飞常准 MCP（`getFlightPriceByCities` 舱位级票价等工具，key 自备）、联网搜 OTA/聚合页面，皆可。无论哪个渠道拿到价：candidates 写 `price` + `priceQueriedAt`、`dataSources` 登记来源，**页面声明「机票价格仅作参考（非实时报价）、以订票页为准」（强制，渲染层已带）**。
- `note` 写机型/是否直飞/经停等乘机信息。
- 已预订的（用户告知）单独高亮，标"已预订"。
- **目的地无民航机场时**（如晋城）：给「最近机场 + 高铁/大巴接驳」组合方案（机场进城交通耗时一并给），高铁段也列建议车次（同条规则：真实存在、给参考票价、标注以 12306 为准）。

## 酒店（按片区 + 价位推荐，不指定单一酒店）

- 先看本次行程各景点的地理分布，**综合选 1-2 个建议住宿片区**（如香港多落在尖沙咀/中环/铜锣湾），写明推荐理由（离哪些点近、交通如何）。
- **每日标注当晚住宿片区（`days[].stayArea`，2026-08-22 拍板）**：大体区域即可（城区/镇名，如「晋城城区」「北留镇（皇城相府旁）」），返程日可省略——排程、车程链、住宿本是一体，当天住哪不该让读者自己猜。每个片区**核一个城区级锚点坐标**（lat/lng 成对、WGS-84，县政府/镇区一级的近似即可）写进 `hotelAreas[].lat/lng`，地图据此画 🏨 锚点；**宁缺勿猜**——锚点也要过县城/镇政府锚点核验（同坐标纪律，参考「礼义 pins 偏 24km」教训），没核到就省略字段。
- 每个片区按 `经济 / 中档 / 高端` 三档各给 1 个真实存在的代表酒店：名称 + 大致每晚价位区间 + 一句话说明（位置/特点）。价位为区间参考，非实时房价。
- **连锁品牌优先（2026-08-21 拍板）**：同档位优先推荐连锁——华住会系（汉庭/全季/桔子/海友/Crystal）、首旅如家系（如家精选/如家商旅/如家·neo/派柏·云）、锦江系（锦江之星/维也纳/麗枫/7 天）、亚朵、东呈/尚美系（尚客优/精途）等——标准化品控、线上可订可退、会员价发票有保障，县城乡镇尤其抗坑；下沉连锁（尚客优/精途等）也算连锁。**连锁未进驻的地区如实降级**：给当地口碑最好的一两家并在 note 注明「非连锁，以近期点评为准」（如王莽岭山上、北留镇），别硬凑。**位置仍优先于品牌**——为住连锁让每天多跑 1 小时车程不值；评分/开业年份写实测口径（踩坑：王莽岭大酒店凭旧印象写 4.7，联网实为 4.4/296 条）。
- **实时价：仅定档后查（2026-08-21 拍板）**：出发日期未定（dateTBD）期间只给参考区间 `priceRange`，**不查实时价**（酒店价随日期变动极大，估算日查了也白查）；用户定档并把页面丢回来重算时，才经官方渠道查——①已装飞猪 skill（酒店搜索，首选）②`travel-plan-viz/tools/hotel_research.py`（Key 用户自备）——回填 `price` + `priceQueriedAt` + 官方 `actionLink`，登记 `dataSources`，页面注明「价格随订位实时变动，以订房页为准」。
- **境外行程补「网友推荐酒店」（2026-08-23 拍板，方法论见下节）**：写入 `hotelAreas[].crowdPicks`（{name, priceNote, note, source}），`priceNote` 必须带实付年份（如"约 ¥720/晚（2025 网友实付）"）并渲染「非实时」脚注，`note` 写实测优缺点一句话。素材**只作定性参考**——坐标/精确现价/营业时间一律不采信该类素材；条数每片区 1–3 家即够，宁缺毋滥。

### 网友实测情报挖掘（crowdPicks 及同类 tips 的方法论，别指望用户递料）

境外酒店光靠官网/连锁清单不够——稀缺情报是「住过的人怎么说的」（水壶/押金/城市税另付/付款链接打不开/离景点步行几分钟）。这套流程要对**任意目的地**自行挖出来，而不是等用户贴现成清单。

**① 检索式正反两向设计（不止「推荐」）**：每个住宿片区 2–3 组关键词——正向「<城市> 酒店 推荐」「<城市> 住宿 <片区>」；反向「<城市> 酒店 避雷 踩坑」（负样本同样重要，能挡掉正向帖里的候选）；候选定下后**逐家复核**「<店名> 踩雷 / 差评」。

**② 信源优先级与降级链（2026-08-23 实测：小红书内容不进通用搜索引擎）**：

1. `tools/xhs_research.py search`（本机 Selenium 已 login 时——小红书站内笔记只有登录会话抓得到：**访客态实测被全屏登录弹窗拦截、0 结果渲染，联网搜「xhs 笔记快照」也基本搜不到（2026-08-23 实测）**，别指望绕过）；
2. 无本地会话 → **中文个人旅记长文**（独立博客/马蜂窝/穷游的第一人称实测长文，信息类型与 xhs 笔记同构，source 如实标「旅记博客」）；
3. **订房平台差评挖掘**：Tripadvisor / Booking 的近期 1–2 星点评逐条摘优缺点（水壶/隔音/隐藏收费类吐槽正是稀缺情报；好评刷得动、差评刷不动），标「订房平台点评摘译」；
4. 都没有 → **整个省略 crowdPicks**（渐进增强不是必需块，绝不用软文凑数）。

**③ 可信度分层（只收前两档）**：**A 实测**＝第一人称、带实付价格与时间、写得出缺点、有实拍；**B 多源印证**＝不同作者独立提到同一家且细节一致（≥2 篇）；**C 丢弃**＝合集带货/旅行社口吻/全是优点没有细节/单店被多篇软文提及但无一处实付价（营销号特征）。价签信息 >2 年的降权或不写价。

**④ 提取（只取定性）**：`{name, priceNote 带实付年份, note 优缺点一句话（实操细节优先：押金/城市税/水壶/付款方式/步行分钟数）, source}`——**来源如实标注**（用户手贴的标「旅友实测」，别冒充自己调研；博客摘的标「旅记博客」）。

**⑤ 对齐行程**：只收匹配 `hotelAreas` 片区的；城郊大店可收但 note 注明权衡（如「离古城步行 18 分钟」）；每片区 1–3 家、好评差评都要有。

**同法泛化**：票务门路（联票/免费档/换岗时刻）与落地微操（机场大巴几号口/车站站台/城市交通卡坑）属同一类「网友实测情报」——同一套「正反检索 → 分层 → 只取定性」流程，写入 tips 时标「<年份> 旅友实测、以官方为准」；其中官方渠道可复核的关键事实（票价/免费时段/闭馆日）仍走官方源双核，不单独依赖网友口径。
